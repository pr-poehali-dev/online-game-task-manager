# Раздел "AI" — план разработки

Новый раздел трекера "Эра" для общения сотрудников с LLM-моделями (текст, изображения, видео,
код) через единый API-ключ [AI Tunnel](https://aitunnel.ru) (OpenAI-совместимый прокси ко всем
провайдерам: OpenAI, Anthropic, Google, DeepSeek, Meta Llama, Mistral, xAI, Qwen, Moonshot AI,
Z AI, MiniMax, Perplexity, Xiaomi, ByteDance Seed, Aion Labs, Sber и др.).

Этот файл — контекст для дальнейшей разработки. Обновляется по мере продвижения по этапам
(отмечать `[x]` у выполненных пунктов).

## Требования (зафиксировано с пользователем)

- **Доступ**: отдельное право `ai_access` в системе прав (как `logs_view`) — включается точечно
  каждому сотруднику через Кабинет → Команда, не по умолчанию всем.
- **Функции**: текстовый чат с выбором модели, генерация изображений, генерация видео, загрузка
  файлов/картинок в чат (vision), отдельный режим помощи с кодом.
- **Бюджет**: у каждого сотрудника — свой месячный лимит трат в рублях/долларах, админ видит
  расход по всем сотрудникам.
- **История**: несколько сохранённых диалогов на пользователя, как в ChatGPT (список чатов слева,
  переключение между ними).
- **Модели**: широкий список лучших моделей каждого провайдера, включая PRO-версии (см. раздел
  "Список моделей" ниже).
- **Интеграция**: отдельный независимый раздел меню, без связи с карточками задач.

## Архитектура

```
Frontend (src/pages/index/Ai*.tsx)
   │  HTTP (fetch, включая SSE-стриминг)
   ▼
Backend (backend/ai/index.py)
   │  proxy → AI Tunnel API (OpenAI-совместимый)
   │  psycopg2 → таблицы ai_chats / ai_messages / ai_usage
   │  boto3 → S3 (загруженные пользователем файлы, сгенерированные картинки/видео)
   ▼
AI Tunnel API (api.aitunnel.ru) — единый ключ AITUNNEL_API_KEY в service_keys
```

Ключевое архитектурное решение: **сервер — единственный, кто видит `AITUNNEL_API_KEY`**.
Frontend никогда не обращается к AI Tunnel напрямую — только через backend-функцию `ai`, которая
проксирует запрос, считает стоимость по ответу API и списывает её с месячного лимита сотрудника.

## Этапы разработки

### Этап 0 — Подготовка

- [ ] Ключ добавляется в раздел "Служебные ключи" (Кабинет → Управление проектом → Служебные
      ключи) — новая группа полей: `AITUNNEL_API_KEY` (секретный).
- [ ] Уточнить у AI Tunnel актуальный base URL и формат ответа `/models` (может отличаться от
      предположений ниже) — сверить при первом реальном запросе в Этапе 2.

### Этап 1 — Права доступа и БД

- [ ] Миграция `V0076__ai_section.sql`:
  - Добавить `ai_access` в `ALL_PERMISSIONS` (`backend/admin/index.py`) и `PermissionKey`
    (`src/lib/auth.tsx`), по аналогии с `logs_view` — попадает в `PRIVILEGED_PERMISSIONS`
    (выдаёт только владелец проекта, т.к. открывает доступ к платному внешнему сервису).
  - Выдать `ai_access: true` владельцу проекта (`WHERE id = 1`), как это сделано для `logs_view`
    в `V0075`.
  - Таблицы:
    ```sql
    CREATE TABLE ai_chats (
        id SERIAL PRIMARY KEY,
        user_id INTEGER NOT NULL REFERENCES users(id),
        title TEXT NOT NULL DEFAULT 'Новый чат',
        mode TEXT NOT NULL DEFAULT 'chat',   -- chat | image | video | code
        model TEXT NOT NULL,
        pinned BOOLEAN NOT NULL DEFAULT false,
        created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
        updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
    );

    CREATE TABLE ai_messages (
        id SERIAL PRIMARY KEY,
        chat_id INTEGER NOT NULL REFERENCES ai_chats(id) ON DELETE CASCADE,
        role TEXT NOT NULL CHECK (role IN ('user', 'assistant', 'system')),
        content TEXT NOT NULL,
        attachments JSONB,        -- [{name,url,contentType,size}] — файлы/картинки/видео
        model TEXT,               -- модель, которой сгенерирован ответ (для assistant)
        cost_usd NUMERIC(10,5),   -- стоимость этого сообщения, если применимо
        created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
    );

    CREATE TABLE ai_usage (
        id SERIAL PRIMARY KEY,
        user_id INTEGER NOT NULL REFERENCES users(id),
        month DATE NOT NULL,             -- первое число месяца, для группировки трат
        spent_usd NUMERIC(10,4) NOT NULL DEFAULT 0,
        limit_usd NUMERIC(10,4) NOT NULL DEFAULT 5,   -- лимит сотрудника по умолчанию
        UNIQUE(user_id, month)
    );
    ```
  - `ai_usage.limit_usd` редактируется админом за сотрудника (аналог `specialization` в
    `UserList.tsx`) — конкретный интерфейс см. Этап 5.

### Этап 2 — Backend: базовый чат (текст)

- [ ] Создать `backend/ai/index.py` по стандартному паттерну (`_cors_headers`, `_current_user` по
      токену, `MAIN_DB_SCHEMA`, JSON-ответы `{'error': ...}` при ошибках).
- [ ] Проверка доступа: `can('ai_access')`-эквивалент на бэке — читать `permissions` пользователя
      из БД, как это делает `backend/logs/index.py` для `logs_view`.
- [ ] `action=list_models` — статический список моделей (см. ниже), группированный по
      провайдерам, с пометкой цены и поддерживаемых возможностей (vision/код/т.д.) — не обязательно
      запрашивать у AI Tunnel `/models` живьём, чтобы не зависеть от сетевых сбоев на каждый рендер
      страницы.
- [ ] `action=send_message` — принимает `chat_id` (или null для нового чата), `model`, `content`,
      `attachments`. Логика:
  1. Проверить остаток месячного лимита в `ai_usage` — если исчерпан, вернуть
     `403 {'error': 'limit_exceeded'}`.
  2. Собрать историю сообщений чата (`ai_messages` по `chat_id`, в хронологии).
  3. Запрос к AI Tunnel: `POST https://api.aitunnel.ru/v1/chat/completions` с заголовком
     `Authorization: Bearer {AITUNNEL_API_KEY}`, телом
     `{"model": ..., "messages": [...], "stream": true}` — формат идентичен OpenAI API.
  4. Ответ сохраняется в `ai_messages`, стоимость (из `usage` в ответе API, либо расчёт по
     тарифу модели × токены) добавляется в `ai_usage.spent_usd`.
  5. Учитывая 5-секундный таймаут облачных функций (см. правило Function Timeout) — для
     обычного (нестримингового) ответа за 5 сек не уложится длинная генерация. **Решение**:
     функция работает в режиме SSE-проксирования, отдавая чанки по мере поступления от AI Tunnel,
     см. следующий пункт. Если стриминг окажется невозможен на используемой платформе облачных
     функций — пользователю нужно будет вручную поднять таймаут функции `ai` в Ядро → Функции.
- [ ] `action=list_chats` / `action=get_chat` / `action=rename_chat` / `action=delete_chat` —
      CRUD диалогов пользователя (только свои, `WHERE user_id = me.id`).
- [ ] `requirements.txt`: `psycopg2-binary`, `boto3` (без дополнительных SDK — используем `requests`
      или `urllib` для прямых HTTP-вызовов к AI Tunnel, т.к. это OpenAI-совместимый REST API).
- [ ] `tests.json` с базовыми проверками (`list_models` без токена → 401, и т.д.).
- [ ] `sync_backend`.

### Этап 3 — Frontend: базовый чат (текст)

- [ ] Новый раздел `'ai'` в `ViewId` (`src/pages/index/sharedTypes.ts`).
- [ ] Пункт меню в `IndexTopbar.tsx` / `IndexSidebar.tsx` — виден только при `can('ai_access')`
      (по аналогии с тем, как `logs_view` скрывает пункт "Логи").
- [ ] Новые файлы (по образцу декомпозиции `Logs.tsx` — несколько небольших компонентов):
  - `src/pages/index/Ai.tsx` — корневой компонент раздела, вся state-логика (текущий чат,
    список чатов, выбранная модель, история сообщений, отправка).
  - `src/pages/index/AiChatList.tsx` — левая колонка со списком диалогов пользователя (как в
    ChatGPT), кнопка "Новый чат", переименование/удаление.
  - `src/pages/index/AiModelPicker.tsx` — выпадающий список моделей, сгруппированный по
    провайдерам (дизайн-референс — приложенный скриншот AI Tunnel: логотип провайдера + список
    моделей, активная подсвечена).
  - `src/pages/index/AiMessageList.tsx` — лента сообщений диалога, рендер markdown +
    подсветка кода в ответах ассистента.
  - `src/pages/index/AiComposer.tsx` — поле ввода, кнопка отправки, индикатор стриминга,
    кнопка прикрепления файла.
- [ ] Рендер markdown-ответов: добавить `react-markdown` + `remark-gfm` (в проекте пока нет —
      `Tiptap` не подходит для рендера чужого markdown-текста, он WYSIWYG-редактор для
      пользовательского ввода). Подсветка кода — `react-syntax-highlighter` или `highlight.js`.
- [ ] SSE-стриминг на фронте: `fetch` + `ReadableStream` (`response.body.getReader()`), без
      сторонних библиотек — постепенно дописывать текст ответа по мере прихода чанков.
- [ ] Индикатор оставшегося месячного лимита сотрудника — небольшой виджет над полем ввода.

### Этап 4 — Вложения, vision, код, изображения, видео

- [ ] Загрузка файлов в чат: переиспользовать паттерн `_upload_image`/base64→S3 из
      `backend/knowledge/index.py` — новый префикс ключа `ai/{chat_id}/{uuid}.{ext}`.
  - Изображения — передаются в модель как `image_url` в сообщении (vision-модели: GPT-4o/5,
    Claude, Gemini).
  - Документы (PDF/txt) — извлечение текста на бэкенде (Bash-подобная логика, но встроенная в
    Python: `pypdf`) и подстановка как текстовый контекст, а не бинарник.
- [ ] Режим "Помощь с кодом" (`mode=code` у чата) — отдельная вкладка/пресет в композере:
  системный промпт заточен под код-ревью/рефактор, в UI — поле для вставки блока кода с
  подсветкой языка и кнопка "скопировать результат".
- [ ] Генерация изображений — `action=generate_image`, запрос к AI Tunnel
      `POST /v1/images/generations` (формат как OpenAI `images/generations`, модели DALL·E/GPT
      Image/Flux и т.д. — уточнить конкретные доступные в AI Tunnel при подключении в Этапе 0).
      Результат заливается в S3 (как это уже делает инструмент `generate_image` платформы) и
      прикрепляется как `attachment` к сообщению ассистента.
- [ ] Генерация видео — `action=generate_video`, аналогично изображениям, но с учётом того, что
      видео обычно генерируется асинхронно (запрос → job id → poll статуса). Потребуется:
      отдельная колонка `ai_messages.job_status` (`pending`/`done`/`failed`) и фоновый пуллинг
      статуса с фронта (`setInterval` пока сообщение в статусе `pending`), либо — если таймаут
      функции не позволит — пользователю потребуется поднять таймаут функции `ai` вручную.

## Список моделей (черновой, для Этапа 2 — `list_models`)

Группировка повторяет интерфейс AI Tunnel (см. приложенный скриншот), в каждой группе — топовые
и практичные модели для рабочих задач команды. Точные ID моделей (строка для API-запроса)
уточняются на Этапе 0 по факту доступности в AI Tunnel — ниже ориентир по названиям:

- **OpenAI** — GPT-5, GPT-5 mini, GPT-4o (vision), o-серия (рассуждающие), GPT Image (генерация
  изображений)
- **Anthropic** — Claude Opus, Claude Sonnet, Claude Haiku (все — vision + код)
- **Google** — Gemini Pro, Gemini Flash (vision), Veo (видео)
- **DeepSeek** — DeepSeek V3, DeepSeek R1 (рассуждающая, сильна в коде)
- **Meta Llama** — Llama 3.1/4 (крупные open-weight модели)
- **Mistral** — Mistral Large, Codestral (код)
- **xAI** — Grok
- **Qwen** — Qwen2.5 Max/Coder
- **Moonshot AI** — Kimi
- **Perplexity** — Sonar (модели с веб-поиском в реальном времени — полезно для ресёрча)
- Остальные провайдеры со скриншота (Z AI, MiniMax, Xiaomi, ByteDance Seed, Aion Labs, Sber) —
  добавляются по мере необходимости, без приоритета на старте.

Отдельно — модели для генерации изображений (GPT Image / Flux / аналоги) и видео (Veo / Sora,
если доступны в AI Tunnel).

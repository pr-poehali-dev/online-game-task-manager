# План: «Проекты» в разделе AI (аналог Perplexity Projects)

Сотрудник складывает свои файлы в **проект**, а ассистент работает с этим проектом **агентно**:
сам находит нужные файлы, читает их и отвечает со ссылками на источники — без ручного
прикрепления вложений к каждому сообщению.

Референс интерфейса — скриншот Perplexity: слева дерево проектов, внутри проекта вкладки
«Обзор / Файлы / Знания / Настройки», справа панель с описанием и сводкой, снизу — поле запуска
сессии прямо в контексте проекта.

## 1. Что уже готово (на этом строим)

| Есть сейчас | Файлы |
|---|---|
| Диалоги, сообщения, режимы chat/code/image/video/document | `backend/ai/chats.py`, `generate.py`, таблицы `ai_chats`, `ai_messages` |

| Два лимита на сотрудника: количество файлов и объём в МБ | `users.ai_file_limit`, `users.ai_size_limit_mb`, раздел «Команда» |
| Извлечение текста из текстовых файлов при загрузке | `_extract_attachment_text` в `backend/ai/common.py` |
| Передача картинок/PDF/видео модели через AI Tunnel | `_history_row_to_message` |
| Лимит трат в рублях на сотрудника | `ai_usage`, проверка в `generate.py` |

**Вывод:** хранилище файлов, лимиты и чат уже есть. Не хватает трёх вещей: сущности «проект»,
поиска по содержимому файлов и агентного цикла, в котором модель сама решает, что прочитать.

---

## 2. Ключевое решение: как ассистент «работает с проектом»

Файлы проекта нельзя просто скидывать в запрос — 50 документов не влезут в контекст модели и
будут стоить огромных денег. Поэтому используем **поиск по смыслу + инструменты модели**:

1. При загрузке файл разбирается на **фрагменты** (chunks) по ~1000 символов.
2. Для каждого фрагмента считается **эмбеддинг** — числовой «отпечаток смысла» (AI Tunnel,
   модель эмбеддингов, копейки за тысячу фрагментов).
3. При вопросе сотрудника ищем 5–10 фрагментов, наиболее близких к вопросу, и отдаём модели
   **только их** вместе со ссылками на файлы-источники.
4. Модель получает **инструменты** (function calling) и сама решает, что делать:
   `search_project_files` (найти по смыслу), `read_file` (прочитать файл целиком),
   `list_project_files` (посмотреть, что вообще есть в проекте). Это и есть «агентность»:
   несколько шагов рассуждения в одном ответе, а не один запрос к модели.

Поиск делаем на **pgvector** (расширение PostgreSQL). Если расширение на сервере недоступно —
фолбэк на полнотекстовый поиск PostgreSQL, интерфейс и логика не меняются.

## 3. База данных (миграции V0084–V0086)

### `ai_projects` — сам проект
| Колонка | Тип | Назначение |
|---|---|---|
| `id` | serial | |
| `user_id` | int | владелец |
| `name` | text | «3d mobile» |
| `description` | text | описание проекта (правая панель) |
| `instructions` | text | постоянная инструкция ассистенту для этого проекта |
| `summary` | text | автосводка по содержимому, обновляется фоном |
| `icon`, `color` | text | оформление карточки |
| `archived` | bool | «В архиве» |
| `created_at`, `updated_at` | timestamptz | |

### `ai_file_chunks` — фрагменты файлов для поиска
| Колонка | Тип | Назначение |
|---|---|---|
| `id` | serial | |
| `file_id` | int → `ai_files` | какой файл |
| `project_id` | int | дубль для быстрой фильтрации |
| `chunk_index` | int | порядковый номер фрагмента |
| `content` | text | сам текст фрагмента |
| `embedding` | vector(1536) | «отпечаток смысла» (при pgvector) |
| `tsv` | tsvector | фолбэк-поиск без pgvector |

### Правки существующих таблиц
- `ai_files`: `+ project_id`, `+ index_status` (`pending`/`ready`/`failed`), `+ pages` (сколько
  фрагментов получилось).
- `ai_chats`: `+ project_id` — диалог принадлежит проекту, при открытии сразу видит его файлы.
- `users`: `+ ai_project_limit` (сколько проектов сотруднику разрешено, по умолчанию 10) —
  третий лимит рядом с двумя существующими, настраивается там же в «Команде».

## 4. Backend

### Новый модуль `backend/ai/projects.py`
CRUD проектов и их содержимого:
- `list_projects` — список с числом файлов, объёмом, датой последней активности
- `create_project` / `update_project` (имя, описание, инструкции) / `delete_project`
  (с очисткой файлов из хранилища) / `archive_project`
- `project_files` — файлы проекта со статусом индексации
- `attach_files` / `detach_files` — перенести уже загруженные файлы в проект
- `project_summary` — пересобрать автосводку по содержимому

### Новый модуль `backend/ai/indexing.py`
- разбор файла на фрагменты: текст и код — по абзацам, PDF — постранично (`pypdf`),
  Word/Excel — через уже установленные `python-docx` / `openpyxl`
- запрос эмбеддингов пачкой к AI Tunnel, запись в `ai_file_chunks`
- `search_chunks(project_id, query, limit)` — поиск по смыслу с фолбэком на полнотекстовый

Индексация запускается сразу после загрузки файла. Файл размечается `index_status='pending'`,
интерфейс показывает «Обрабатывается…», по готовности — «Готов к поиску».

> ⚠️ Ограничение платформы: у функции есть таймаут (по умолчанию 5 секунд). Большой PDF за один
> вызов проиндексировать не получится, поэтому индексация идёт **порциями**: фронт вызывает
> `index_step` в цикле, пока файл не будет готов, показывая прогресс. Это надёжнее, чем просить
> пользователя поднимать таймаут.

### Агентный цикл в `backend/ai/agent.py`
Отдельное действие `project_chat`:
1. Собираем системный промпт: инструкции проекта + список файлов + автосводка.
2. Отдаём модели инструменты `search_project_files`, `read_file`, `list_project_files`.
3. Модель просит вызвать инструмент → выполняем → возвращаем результат → повторяем.
   Максимум 4 шага (защита от зацикливания и лишних трат).
4. Финальный ответ сохраняем вместе со **списком источников** — какие файлы использовались.
5. Стоимость каждого шага суммируем и списываем в `ai_usage` — лимит трат работает как раньше.

Ограничение таймаута решается тем же приёмом: шаги агента возвращаются фронту по одному, он
показывает «Ищу в файлах…», «Читаю договор.pdf…» — это ещё и понятнее для пользователя, чем
молчаливое ожидание.

## 5. Интерфейс

### Список проектов (левая колонка раздела AI)
Над списком диалогов появляется секция «Проекты» со сворачиваемым деревом: проект → его диалоги.
Кнопка «Новый проект». Диалоги вне проектов остаются как есть.

### Страница проекта
- **Шапка:** иконка, название, кнопки «Поделиться» (на будущее) и «…»
- **Вкладки:** Обзор / Файлы / Знания / Настройки
- **Обзор:** список сессий проекта, фильтры «Все / Мои / В архиве», внизу поле «Начать сессию
  в {проект}» — тот же композер, что в обычном чате
- **Файлы:** дерево файлов проекта (переиспользуем `AiFilesPanel`), загрузка перетаскиванием,
  статус индексации у каждого файла, расход обоих лимитов
- **Знания:** автосводка по проекту + постоянные инструкции ассистенту
- **Настройки:** имя, описание, иконка, архивация, удаление
- **Правая панель:** описание, сводка, контекст — как на референсе

### В переписке
Под ответом ассистента — плашка «Источники: договор.pdf · смета.xlsx» с переходом к файлу.
Пока идут шаги агента, показывается, что именно он делает.

## 6. Лимиты и права

Ничего нового изобретать не нужно — расширяем то, что уже работает:
- файлы проекта расходуют **существующие** лимиты количества и объёма сотрудника;
- добавляется третий лимит — **число проектов** (`users.ai_project_limit`), настраивается в
  «Команде» рядом с двумя другими;
- индексация и агентные шаги стоят денег → списываются в **тот же** месячный лимит трат;
- доступ к проектам — по имеющемуся праву `ai_access`, проекты строго приватные (чужие не видны).

## 7. Порядок работ

| Этап | Что делаем | Результат для пользователя |
|---|---|---|
| **1** | Миграции, `projects.py`, список и страница проекта, привязка файлов | Можно создавать проекты и складывать в них файлы |
| **2** | `indexing.py`, разбор на фрагменты, эмбеддинги, статусы | Файлы становятся «искомыми», видно прогресс |
| **3** | `agent.py`, инструменты, источники в ответах | Ассистент сам находит нужное в проекте |
| **4** | Автосводка, инструкции проекта, вкладка «Знания» | Ассистент помнит контекст проекта между сессиями |
| **5** | Лимит проектов в «Команде», архив, оформление | Администратор управляет нагрузкой |

Каждый этап самодостаточен: после первого уже есть рабочая функция, остальное наращивается
сверху, ничего не ломая.

---

## 8. Риски и как их обходим

| Риск | Решение |
|---|---|
| Таймаут функции на больших файлах | Индексация и шаги агента порциями, с прогрессом |
| Нет pgvector на сервере | Автофолбэк на полнотекстовый поиск, интерфейс не меняется |
| Рост трат на эмбеддинги | Дешёвая модель эмбеддингов, индексируем один раз, стоимость идёт в общий лимит |
| Раздувание хранилища | Работают оба существующих лимита + очистка при удалении проекта |
| Агент «зациклился» | Жёсткий потолок в 4 шага на ответ |

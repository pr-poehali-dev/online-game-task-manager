бага в .gitignore (правило `logs` без ведущего слэша случайно игнорировало папку backend/logs/,

## Цель задачи
Раздел кабинета **"Логи"** (наравне с "Патчи"/"Патчноуты"): пользователь выбирает сервер (тот же
список, что в "Патчах" — таблица `servers`), выбирает вид лога (`cached`/`server`/`npc`), видит
разобранную таблицу событий с человекочитаемыми именами вместо числовых id (item_id → предмет,
npc_id → нпс, skill_id → скилл, action_id → действие). Прообраз — desktop-парсер пользователя
"LogParser AdvExt" (Actor Name/Account/IP, Item ItemID/ItemDB/Enchant, Action, диапазон дат, Nums
1-5 как доп.фильтры числовых полей), который переписывается на Python внутри веб-приложения.

## Формат файлов лога (подтверждено на реальных образцах)
Имя: `{ГГГГ-ММ-ДД}-{HHMM}-{NN}-{тип}-in{0|1}.log`, например `2026-08-07-10020-01-server-in0.log`.
Файлы нарезаны примерно каждые 30 минут (см. уточнение пользователя — не почасово, как думали
раньше). Кодировка **cp1251** (не utf-8!). Формат строки — CSV без экранирования, разделитель `,`,
конец строки `\r\n`, **ровно 27 полей** во всех трёх типах логов (cached/server/npc).

Индексы полей (0-based в коде, было расшифровано вручную сверкой с образцами):
- `[0]` — время `"08/07/2026 20:00:00.010"`
- `[1]` — action_id
- `[22]` — имя персонажа-исполнителя (actor)
- `[23]` — логин/аккаунт исполнителя
- `[24]` — имя цели (target), если есть
- `[25]` — логин цели
- Для `action=901/902` (BuyItem/SellItem, cached-лог): `[19]` = item_id
- Для `action=403` (CastSkill) / `1112` (PCKilledNPC), server-лог: `[16]` = skill_id
- Остальные ~150+ action_id ещё не расшифрованы по номерам полей — осознанно отложено, карта
  расширяется по мере вопросов пользователя (см. `ACTION_ITEM_FIELD`/`ACTION_SKILL_FIELD` в
  `index.py`). Для неизвестных action_id парсер просто не резолвит item/skill (не баг).

## Источник справочников имён — ВАЖНОЕ УТОЧНЕНИЕ от пользователя (актуально!)
Изначально предполагалось использовать статичный снимок `settings.7z` (архив от desktop-парсера,
4 файла: action_ids.txt/item_ids.txt/npc_ids.txt/skill_ids.txt) для ВСЕХ 4 типов id. **Пользователь
поправил**: это НЕВЕРНО для item/npc/skill — они должны резолвиться из **АКТУАЛЬНОГО дерева
патчей конкретного сервера** (`itemname-e.dat`/`npcname-e.dat`/`skillname-e.dat`, те же файлы,
что раздел "Патчи" уже умеет расшифровывать/парсить через DDF), а НЕ из статичного снимка 2023
года. Статичный справочник актуален и остаётся ЕДИНСТВЕННЫМ источником **только для action_id**
(это внутренний код действия сервера, не игровой ресурс — в дереве патчей его нет и не может быть).

Реализовано (см. `backend/logs/game_lookup.py`):
- `action_ids.tsv` (361 строка, `id\tName`, получен от пользователя, лежит в
  `backend/logs/reference/action_ids.tsv`) — читается напрямую с диска, кэш в памяти процесса.
- item/npc/skill — `game_lookup.build_lookup(cur, schema, server, kind)` расшифровывает нужный
  `.dat` файл сервера прямо из S3 (таблица `patch_files`, тот же bucket что "Патчи"), парсит через
  DDF (`ddf_parser.iter_records` + `ddf_registry.match_ddf`/`ddf_registry_c4.match_ddf` — C4-сервер
  `c4x1` использует отдельный реестр схем, как и в `backend/patches`), строит словарь `{id: name}`,
  кэширует в памяти процесса по ключу `(server, kind)`. Если файл ещё не загружен в дерево патчей
  этого сервера — просто пустой словарь (не ошибка, лог показывается с сырыми id).
- Раньше (устаревший вариант, УЖЕ УБРАН) были статичные `item_ids.tsv`/`npc_ids.tsv`/
  `skill_ids.tsv` в `reference/` — они больше не используются и не восстановлены после потери
  файлов (не нужны, см. выше).

## Реальная структура каталогов на VPS — РЕШЕНО
Пользователь пересобрал структуру на VPS под ожидания кода: под `servers.logs_dir` лежат три
подпапки `server/`, `npc/`, `cashed/` (подтверждено скриншотом). **ВАЖНЫЙ НЮАНС**: сами файлы лога
называются с полным словом `...-cached-...log` (подтверждено `LOG_FILENAME_RE`), но папка на
диске называется `cashed` (с опечаткой, реальное имя каталога на сервере пользователя) — это
несовпадение зафиксировано явно в коде через словарь `LOG_TYPE_DIR = {'cached': 'cashed', 'server':
'server', 'npc': 'npc'}` в `backend/logs/index.py`: `log_type` (используется в API и regex имени
файла) всегда `'cached'`, а при построении SFTP-пути (`remote_dir`/`remote_path`) подставляется
`LOG_TYPE_DIR[log_type]`, то есть `cashed`. Если пользователь позже переименует папку на сервере в
правильное `cached` — нужно поправить `LOG_TYPE_DIR['cached'] = 'cached'` (одна строка).

## Реальный workflow пользователя (снятие логов с прода) — для сверки ожиданий UI
Пользователь вручную скачивает нужные по дате/времени файлы с live-сервера (нарезка каждые 30
минут) в локальную папку рядом с desktop-парсером, открывает парсер, задаёт фильтры (тип лога,
диапазон дат, ник/аккаунт/IP персонажа, item id/db id/enchant, action, 5 доп. числовых полей),
запускает разбор, может сохранить результат в HTML. Наш веб-парсер идёт другим путём — тянет файлы
напрямую по SFTP с VPS по требованию (без ручного скачивания пользователем), см. `action=list_files`
+ `action=get_log` в `backend/logs/index.py`.

## Архитектура (реализовано)
- `backend/logs/index.py` — handler, action-роутинг (`list_files`, `get_log`), право `logs_view`
  (отдельное от `patch_edit`, читается из `users.permissions`, миграция
  `db_migrations/V0075__add_logs_dir_and_logs_view_permission.sql`), SFTP через `paramiko`
  (креды в `service_keys`: `LOGS_SFTP_HOST/PORT/USER/PASSWORD`, единый хост на все сервера),
  путь конкретного сервера — колонка `servers.logs_dir`.
- `backend/logs/game_lookup.py` — резолвинг item/npc/skill из дерева патчей (см. выше).
- `backend/logs/reference/action_ids.tsv` — статичный справочник action_id → имя (единственный
  источник для action).
- `backend/logs/requirements.txt` — `psycopg2-binary`, `paramiko`, `boto3` (нужен для S3-доступа
  к дереву патчей в `game_lookup.py`; `paramiko`/`boto3` уже есть в общем self-hosted
  `deploy/requirements.txt` из-за `backend/patches`, доп. действий на self-hosted не требуется).
- `backend/logs/tests.json` — 3 теста (OPTIONS, 401 без токена на оба действия).
- Фронтенд: `src/pages/index/Logs.tsx` — выбор сервера/типа лога/файла, фильтры
  (игрок/предмет/действие), таблица, пагинация; `LOGS_URL` в `src/pages/index/sharedHelpers.ts`;
  `ViewId`/`NAV_ITEMS`/монтирование — как у "Патчей" (сделано в предыдущих сессиях, детали см.
  git log, не переисследовано заново в этой сессии).

# Раздел «AI» — как устроен и как работает

Технический справочник по разделу «AI» трекера «Эра» — общение сотрудников с ИИ-моделями
(текст, код, изображения, видео) через единый ключ [AI Tunnel](https://aitunnel.ru).

Связанные документы:
- `AI_MANAGER_PLAN.md` — исходный план разработки по этапам (все 6 этапов закрыты).
- `docs/ai-tunnel-api-reference.md` — сохранённая официальная документация внешнего API.

Этот файл — **контекст для будущих доработок**: что где лежит, как течёт запрос, какие есть
известные ограничения и грабли. Обновлять при значимых изменениях раздела.

---

## 1. Архитектура в двух словах

```
Frontend  src/pages/index/Ai*.tsx  (React + TS)
   │  fetch → одна облачная функция `ai`, все действия через поле action в теле/query
   ▼
Backend   backend/ai/index.py      (Python 3.11, один handler, ~1100 строк)
   ├─ psycopg2 → ai_chats / ai_messages / ai_usage / ai_prompt_templates
   ├─ boto3    → S3 (вложения, сгенерированные картинки и видео)
   └─ urllib   → AI Tunnel API (api.aitunnel.ru)
```

**Ключевое архитектурное решение:** `AITUNNEL_API_KEY` видит только сервер. Он лежит в таблице
`service_keys` (заполняется в Кабинет → Служебные ключи), фронт к AI Tunnel никогда не ходит
напрямую. Backend проксирует запрос, читает готовую стоимость из `usage.cost_rub` ответа и
прибавляет её к месячному расходу сотрудника.

**Доступ:** отдельное привилегированное право `ai_access` (как `logs_view`). По умолчанию `false`
даже у роли `admin` — выдаёт точечно владелец проекта в Кабинет → Команда. Регистрация ключа
права: `backend/admin/index.py` (`ALL_PERMISSIONS`/`PRIVILEGED_PERMISSIONS`), `src/lib/auth.tsx`
(`PermissionKey`), `src/pages/admin/adminShared.ts` (`OWNER_ONLY_PERMISSION_GROUPS`).

## 3. Схема базы данных

### `ai_chats` — диалоги
| Колонка | Тип | Комментарий |
|---|---|---|
| `id` | SERIAL PK | |
| `user_id` | INTEGER FK → users | владелец диалога, чужие не видны |
| `title` | TEXT | автогенерируется из первого сообщения, редактируется inline |
| `mode` | TEXT | `chat` \| `code` \| `image` \| `video` |
| `model` | TEXT | модель, с которой диалог создан |
| `pinned` | BOOLEAN | закрепление **всего диалога** в списке слева |
| `created_at` / `updated_at` | TIMESTAMPTZ | |

Индекс: `idx_ai_chats_user_id`.

### `ai_messages` — сообщения
| Колонка | Тип | Комментарий |
|---|---|---|
| `id` | SERIAL PK | |
| `chat_id` | INTEGER FK → ai_chats | |
| `role` | TEXT | `user` \| `assistant` \| `system` |
| `content` | TEXT | текст; у картинок/видео от ассистента — пустая строка |
| `attachments` | JSONB | `[{id, name, url, size, contentType, text?}]` |
| `model` | TEXT | фактическая модель ответа (важно при `auto`) |
| `cost_rub` | NUMERIC(10,5) | из `usage.cost_rub` ответа AI Tunnel |
| `job_id` | TEXT | id асинхронной задачи видео |
| `job_status` | TEXT | `pending` \| `done` \| `failed` |
| `pinned` | BOOLEAN | закрепление **одного ответа** внутри диалога |
| `created_at` | TIMESTAMPTZ | |

Индекс: `idx_ai_messages_chat_id`.

### `ai_usage` — лимиты и траты
`(user_id, month)` UNIQUE, `month` = первое число месяца. `spent_rub` NUMERIC(10,2),
`limit_rub` NUMERIC(10,2) DEFAULT 300. Лимит редактируется админом (Кабинет → Команда), сводка по
всем — Кабинет → Статистика (`action=ai_usage_summary` в `backend/admin/index.py`).

### `ai_prompt_templates` — шаблоны промптов
`user_id`, `icon`, `category`, `title`, `description`, `prompt`, `recommended_mode`, `sort_order`.
Полностью приватны: не копируются между пользователями, у нового сотрудника список пуст.

> **Важно:** FK без `ON DELETE CASCADE` (ограничение инструмента миграций) — зависимые записи
> чистятся вручную в коде backend.

## 4. Действия backend (`action=...`)

### Каталог и служебное
- **`list_models`** (`group=chat|images|videos`) — прокси публичного каталога AI Tunnel, in-memory
  кеш 10 минут (`_MODELS_CACHE`). Ключ не нужен, отдаётся сырой ответ.
- **`usage`** — `{spentRub, limitRub}` текущего пользователя за текущий месяц.
- **`balance`** — общий остаток аккаунта AI Tunnel. Только для `team_manage`/`admin`.

### Диалоги
- **`list_chats`** — свои диалоги, сортировка `pinned DESC, updated_at DESC`.
- **`get_chat`** (`chatId`) — диалог + **все** его сообщения.
- **`rename_chat`**, **`set_pinned`**, **`set_message_pinned`** — точечные UPDATE.
- **`generate_title`** (`chatId`) — осмысленное название диалога по первому обмену на дешёвой
  модели `gpt-5-nano`. Фронт зовёт фоном после первого ответа; при ошибке молча оставляет старое
  название. Внутрь `send_message` НЕ встроено намеренно — иначе добавилось бы к времени ответа.
- **`search_messages`** (`query`, минимум 2 символа) — поиск по содержимому всех диалогов
  пользователя, до 50 совпадений, каждое со снипетом вокруг найденного слова.
- **`regenerate`** (`chatId`, `model`) — удаляет ПОСЛЕДНИЙ ответ ассистента и заново спрашивает
  модель по той же истории. Модель можно передать другую — так сравнивают ответы. Только для
  текстовых режимов; `nothing_to_regenerate`, если последнее сообщение не от ассистента.
- **`delete_chat`** — сначала `_delete_chat_attachments()` чистит S3, потом DELETE сообщений и чата.

### Шаблоны промптов
- **`list_templates`** / **`create_template`** / **`update_template`** / **`delete_template`** —
  CRUD, всё скоупится по `user_id`.

### Загрузка файлов
- **`upload_attachment`** — маленький файл одним запросом (base64 → S3 `ai/uploads/{uuid}.{ext}`).
- **`file_init` → `file_chunk`×N → `file_complete`** (и **`file_abort`**) — большой файл кусочками.
  Куски складываются в `ai/_chunks/{fileId}/{NNNNNN}`, метаданные в `meta.json`, после сборки
  куски удаляются. Паттерн 1:1 с `backend/patches/index.py`.

  **Зачем:** одиночный HTTP-запрос к облачной функции ограничен ~3.5 МБ на уровне прокси
  платформы — это нельзя изменить настройками. `MAX_UPLOAD_SIZE = 200 МБ`.

  Для текстовых файлов при загрузке сразу извлекается содержимое в поле `text`
  (`_extract_attachment_text`), чтобы не ходить в S3 при каждой отправке сообщения.

### Генерация и общение
- **`send_message`** — `model`, `content`, `chatId?`, `mode`, `attachments[]`. Проверяет лимит,
  создаёт чат при необходимости, собирает историю (последние **30** сообщений), для `mode='code'`
  добавляет `CODE_SYSTEM_PROMPT`, POST `/chat/completions` с `max_tokens: 4000`, сохраняет ответ,
  прибавляет `cost_rub` к `ai_usage`.
- **`generate_image`** — синхронный POST `/images/generations` (timeout 90 с). Декодирует
  `data[].b64_json` (может быть несколько при `n>1`), заливает в S3 `ai/images/{uuid}.{ext}`.
- **`generate_video`** — асинхронный POST `/videos`, сохраняет `job_id` + `job_status='pending'`,
  отвечает мгновенно.
- **`check_video_job`** (`messageId`) — GET `/videos/{id}`; при `completed` скачивает MP4
  (`/content?index=0`), заливает в S3 `ai/videos/{uuid}.mp4`, списывает стоимость.

### Как вложения попадают в модель (`_history_row_to_message`)
| contentType | Формат для AI Tunnel |
|---|---|
| `image/*` | `{type: "image_url", image_url: {url}}` |
| `application/pdf` | `{type: "file", file: {filename, file_data}}` |
| `video/*` | `{type: "video_url", video_url: {url}}` |
| текстовый (есть поле `text`) | вставляется в текст запроса как ```` ```блок``` ```` |

Текст всегда идёт первым элементом — так рекомендует документация AI Tunnel.

## 6. Что важно знать про AI Tunnel

- **Base URL** `https://api.aitunnel.ru/v1`, заголовок `Authorization: Bearer sk-aitunnel-...`.
  Формат полностью OpenAI-совместимый.
- **Деньги в рублях.** Каждый ответ содержит `usage.cost_rub` — считать самим не нужно.
- **Каталог моделей публичный**, без ключа: `GET /public/aitunnel/models/{chat|images|videos}`.
  Отдаёт актуальные цены, контекст, `modalities`. Модели не хардкодим — список живой.
- **Модель `auto`** — AI Tunnel сам подбирает модель под задачу.
- **Генерация изображений синхронна**, результат всегда `b64_json` (прямых URL нет).
  `input_references` превращает генерацию в image-to-image редактирование.
- **Генерация видео асинхронна:** POST → поллинг → скачивание. **Отмены нет** — деньги
  списываются сразу при старте, независимо от результата.
- **Коды ошибок совпадают с HTTP:** 400 неверные параметры, 401 неверный ключ, 402 нет баланса,
  403 модель запрещена ключу, 429 rate limit. На фронте разобраны в `AITUNNEL_STATUS_MESSAGES`.
- **Стриминг (SSE) сознательно не используется** — платформа не даёт надёжно держать поток дольше
  таймаута функции. Вместо этого обычный request/response + спиннер «Модель думает…».

## 7. Поток данных на фронте

`Ai.tsx` держит всё состояние и является единственной точкой обращения к backend.

```
mode (chat|code|image|video)
  └→ modelGroup (chat|images|videos) → loadModels() → AiModelPicker
activeChatId (в localStorage)
  └→ loadChat() → messages → AiMessageList
chats → AiChatList
usage → полоса лимита в обоих композерах, limitExceeded блокирует отправку
pendingAttachments → AiComposer (превью, удаление до отправки)
```

Ключевые детали:
- **Оптимистичный рендер:** отправленное сообщение сразу появляется с `id = -Date.now()`; при
  ошибке удаляется, а текст и вложения возвращаются в композер.
- **Таймаут запроса** `SEND_TIMEOUT_MS = 120000` через `AbortController` — без него соединение
  иногда рвалось молча и сообщение «зависало».
- **Поллинг видео** каждые 6 с для сообщений с `jobStatus='pending'`, дедупликация через
  `pollingRef`.
- **Память выбора модели** — по каждой группе отдельно: `localStorage['ai_last_model_{group}']`.
- **Загрузка файла:** ≤2 МБ — одним запросом, больше — кусками по 1.5 МБ с прогресс-баром.

## 8. Известные ограничения и грабли

1. **Таймаут функции.** По умолчанию 5 с. Обычный текстовый чат укладывается, но **генерация
   изображений и vision-запросы стабильно упираются в 504**. Нужно вручную поднять таймаут
   функции `ai` в Ядро → Функции → Настройки (минимум 30–60 с). Изменить из кода нельзя.
   В логах выглядит как `Code: 504 ... Execution timeout exceeded` / `JobExecutionTimeoutExceeded`.

2. **Модели врут о своих возможностях.** Каталог заявляет `max_n: 10`, но, например,
   `seedream-4.5` при `n=2` возвращает одну картинку (и списывает как за одну). Проверено
   эмпирически; `gpt-image-1-mini` при `n=2` отдаёт две. Это ограничение провайдера, не баг кода.

3. **Соотношение сторон при редактировании по референсу.** Если передать `aspect_ratio` вместе с
   `input_references`, модель насильно растянет результат под указанный формат вместо сохранения
   пропорций исходного фото. Исправлено: при наличии референсов параметр не отправляется, а
   селектор в UI блокируется.

4. **Null byte в текстовых файлах.** `\x00` — валидный UTF-8, но PostgreSQL не умеет его хранить
   ни в `text`, ни в `jsonb` (SQLSTATE 22P05). Вырезается в `_extract_attachment_text`.

5. **Лимит тела запроса ~3.5 МБ** на уровне прокси платформы — отсюда кусочная загрузка.

6. **Стоимость видео** списывается провайдером при старте, но в `ai_usage` попадает только когда
   поллинг увидит `completed`. Если задача провалилась или пользователь закрыл вкладку — расход в
   нашей статистике не отразится.

## 9. Слабые места кода (кандидаты на рефакторинг)

- `backend/ai/index.py` — **1106 строк** в одном файле, роутинг цепочкой `if action == ...`.
  Просится разбиение на модули: `chats.py`, `files.py`, `generate.py`, `templates.py`.
- `Ai.tsx` — **551 строка**, три почти одинаковых обработчика (`handleSend`,
  `handleGenerateImage`, `handleGenerateVideo`) с дублирующимся try/catch, оптимистичным
  рендером и разбором ошибок. Просится общий хук `useAiRequest`.
- `get_chat` грузит **все** сообщения диалога без пагинации — на длинных чатах это тяжело.
- `tests.json` покрывает только 401/OPTIONS — ни один бизнес-сценарий не тестируется.
- Ошибки загрузки референса в `AiGenerateComposer.handleAddReference` глотаются молча
  (`catch {}`) — пользователь не понимает, почему превью не появилось.
- Нет ретраев ни на одном сетевом вызове; при 429 (rate limit) пользователь просто видит ошибку.

## 11. Чеклист при доработке раздела

- Изменил backend → обязательно `sync_backend`, тесты должны проходить.
- Меняешь схему БД → только через `migrate_db`, миграции forward-only.
- Новый параметр генерации → сверься с `docs/ai-tunnel-api-reference.md`, добавь и на фронт
  (`AiTypes.ts` + композер), и в `payload` соответствующего action.
- Что-то «зависает» → сначала `get_logs` для `frontend`, потом `backend/ai`; ищи 504 и 499.
- Работаешь с картинками — помни, что провайдеры игнорируют часть параметров молча; проверяй
  фактический результат (реальные размеры файла), а не только код ответа.

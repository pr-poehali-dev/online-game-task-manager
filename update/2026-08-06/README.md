# Обновление от 6 августа

Одно точечное изменение — в разделе «Патчи» ошибки заливки файла на VPS
лаунчера («Б»/«П») и сверки с лаунчером («Сверить с лаунчером») теперь
показывают технический код ошибки прямо в интерфейсе, без похода в логи
сервера.

---

## 1. Код ошибки в сообщении о сбое заливки/сверки с лаунчером

### Что было не так
При сбое заливки файла на VPS лаунчера или сверки с лаунчером фронтенд
показывал только общую фразу «Не удалось залить файл на сервер лаунчера —
проверьте подключение и попробуйте ещё раз» (или аналогичную для сверки).
Backend при этом уже возвращал точный технический код (например
`ssh_connect_error_TimeoutError`, `ssh_error_AuthenticationException`), но
фронтенд его отбрасывал — узнать точную причину сбоя (неверный хост,
неверный логин/пароль, нет прав на запись и т.д.) можно было только через
серверные логи backend-функции `patches`, что на self-hosted недоступно
через инструменты редактора.

### Что изменилось
Для всех кодов ошибок, которые не разобраны отдельным человекочитаемым
текстом (`launcher_paths_not_configured`, `ssh_not_configured`,
`file_hash_missing`, `xml_verify_failed` — эти сообщения не изменились),
теперь в конец фразы добавляется технический код в скобках, например:
`Не удалось залить файл на сервер лаунчера — проверьте подключение и
попробуйте ещё раз (код: ssh_error_AuthenticationException)`.

Значение кода:
- `ssh_connect_error_TimeoutError` — VPS не отвечает на указанном
  хосте/порту (неверный адрес или закрыт файрволом)
- `ssh_connect_error_AuthenticationException` — неверный логин/пароль в
  «Управление проектом → Служебные ключи»
- `ssh_error_SSHException` / `ssh_error_IOError` — соединение установилось,
  но сорвалось при записи файла (обычно нет прав на папку или диск
  переполнен)

### Файлы для переноса
```
src/pages/index/usePatches.ts
```

### Как перенести
```bash
cd /var/www/era   # корень вашего проекта на сервере

cp update/2026-08-06/src/pages/index/usePatches.ts src/pages/index/usePatches.ts

npm install
npm run build
sudo systemctl restart era-backend   # backend не менялся, можно пропустить
```
Backend не менялся — миграции БД и перезапуск `era-backend` не требуются,
достаточно пересобрать фронтенд.

### Проверка
- В разделе «Патчи» попробуйте залить файл на сервер с заведомо неверными
  SSH-реквизитами (или отключите VPS) — сообщение об ошибке должно
  содержать `(код: ...)` в конце.
- То же самое проверьте на кнопке «Сверить с лаунчером».

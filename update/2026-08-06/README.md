# Обновления от 6 августа

Четыре темы за сегодня:
1. **Новое:** участник может сам задать себе никнейм и загрузить свою аватарку в личном кабинете — без привязки к данным Telegram, и эти данные больше не перезаписываются при следующем входе через бота.
2. **Новое:** в разделе «Патчи» переименование и удаление теперь работают для **любой вложенной папки** дерева (не только для корневых, как раньше).
3. **Новое:** журнал активности (кабинет → «Журнал») теперь фиксирует все действия с файлами патчей — загрузку, удаление, правку `.dat`-записей, заливку в лаунчер, создание/удаление/переименование папок.
4. **Новое:** в режиме «Выбрать файлы» раздела «Патчи» отмеченные файлы теперь можно скачать одним архивом, а также появился чекбокс у КАЖДОЙ папки — отмечает разом все файлы внутри неё (в т.ч. во вложенных подпапках).
5. Плюс более раннее точечное изменение: технический код ошибки в сообщении о сбое заливки/сверки с лаунчером (см. раздел 5 — то же самое, что было в предыдущей версии этой папки, ничего нового переносить дважды не нужно, файл уже включает это изменение).

## 1. Свой никнейм и аватарка в личном кабинете

### Что было не так
Имя и фото участника брались строго из Telegram-профиля (`first_name`,
`last_name`, `photo_url`) и **перезаписывались этими же данными при каждом
новом входе через Telegram** — если админ вручную менял имя участнику
(кнопка «Изменить имя» в разделе «Команда»), либо сам участник хотел
использовать другое отображаемое имя/фото, эти изменения слетали при
следующем логине.

### Что изменилось
- В таблицу `users` добавлены две новые колонки: `nickname` и `avatar_url`.
- Если они заполнены — используются везде вместо `first_name`/`photo_url`
  (вход, проверка сессии, список команды, журнал активности, тестовый вход
  под участником). Поля из Telegram (`first_name`/`last_name`/`photo_url`)
  по-прежнему обновляются при каждом логине через бота, но уже не влияют на
  то, что видно в интерфейсе, если задан свой никнейм/аватар.
- В разделе «Мой профиль» кабинета появилась возможность:
  - нажать на карандаш у имени и вписать свой никнейм (до 60 символов,
    Enter/кнопка «OK» сохраняют, Esc отменяет);
  - навести на аватарку и нажать иконку камеры — загрузить своё фото
    (до 5 МБ, JPG/PNG/WebP), кнопка «Сбросить фото» возвращает аватарку из
    Telegram.
- Новые backend-действия в `auth`: `set_nickname`, `upload_avatar`,
  `remove_avatar` — доступны только самому пользователю по его же токену
  сессии (не требуют прав администратора).

⚠️ **Загрузка аватарки использует то же самое S3/MinIO-хранилище**, что и
все остальные файлы проекта (задачи, патчи и т.д.) — те же переменные
`AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` / `S3_ENDPOINT` /
`S3_PUBLIC_URL`, которые вы уже настраивали в кабинете → «Управление
проектом» → «Хранилище (MinIO)». Отдельно настраивать ничего не нужно —
если раздел «Хранилище» у вас уже заполнен и работает (например туда уже
успешно грузятся файлы патчей), загрузка аватарки заработает сразу после
переноса файлов ниже. Сам раздел «Хранилище (MinIO)» (`backend/storage-config`,
`src/pages/cabinet/CabinetStorage.tsx`) сегодня не менялся и в этот апдейт
не входит.

  была).

## 2. Переименование и удаление вложенных папок в «Патчах»

### Что было не так
В дереве файлов раздела «Патчи» кнопки переименования и удаления папки были
доступны только для папок **верхнего уровня** (`System`, `l2text` и
подобные, а также созданные вручную корневые папки). Вложенные подпапки
(например `l2text/workshop`) не имели своей записи в базе — они существуют
только как общий префикс пути у файлов внутри, поэтому управлять ими было
нельзя вообще.

### Что изменилось
Для любой вложенной папки (любого уровня вложенности) при наведении
появляются:
- **карандаш** — переименовать папку. Действие физически переносит все
  файлы внутри на новый путь (в S3 и в базе), поэтому может занять время,
  если файлов много;
- **корзина** — удалить папку целиком со всем содержимым, с подтверждением.

Права остались прежними: переименование требует права на редактирование
раздела «Патчи» (`patch_edit`), удаление — отдельного права на удаление
файлов (`patch_delete_files`), как и раньше для отдельных файлов.

Переименование/удаление папки верхнего уровня по-прежнему работает
по-старому — там кнопки меняют только отображаемое имя (не трогая сами
файлы) либо удаляют папку, только если она пустая.

```
backend/patches/tests.json
src/pages/index/Patches.tsx
src/pages/index/PatchesTree.tsx
src/pages/index/PatchesTreeFolder.tsx
src/pages/index/usePatches.ts
```

### Как перенести
```bash

cp update/2026-08-06/backend/patches/index.py backend/patches/index.py
cp update/2026-08-06/backend/patches/tests.json backend/patches/tests.json
cp update/2026-08-06/src/pages/index/Patches.tsx src/pages/index/Patches.tsx
cp update/2026-08-06/src/pages/index/PatchesTree.tsx src/pages/index/PatchesTree.tsx
cp update/2026-08-06/src/pages/index/PatchesTreeFolder.tsx src/pages/index/PatchesTreeFolder.tsx
cp update/2026-08-06/src/pages/index/usePatches.ts src/pages/index/usePatches.ts
```

Backend содержит только новые действия (`rename_folder`, `delete_folder`),
миграций БД для этого раздела не требуется.

### Проверка
- В «Патчах» раскройте любую корневую папку с вложенной подпапкой —
  наведите на подпапку, должны появиться карандаш и корзина.
- Переименуйте вложенную папку — файлы внутри должны остаться на месте по
  содержимому, но путь должен обновиться.
- Удалите вложенную папку с файлами (тестовую, не боевую!) — все файлы
  внутри должны исчезнуть из дерева и из хранилища.

папки, прикрепление/открепление файла к задаче. Каждая запись видна в

## 4. Скачивание выбранных файлов архивом и чекбокс на папке

### Что было не так
В режиме «Выбрать файлы» раздела «Патчи» отмеченные чекбоксами файлы можно
было только удалить пачкой — скачать их одним архивом было нельзя (только
по одному через кнопку «Скачать файл» у каждой строки, либо архивом всё
дерево сервера целиком). Также чекбокс был только у отдельных файлов —
чтобы выбрать все файлы внутри папки (например перед скачиванием или
удалением), приходилось отмечать их по одному.

### Что изменилось
- В блоке режима выбора (шапка над деревом, когда включено «Выбрать файлы»)
  рядом с кнопкой «Удалить выбранное» появилась кнопка **«Скачать
  архивом»** — собирает отмеченные файлы в один `.zip` и открывает ссылку
  на скачивание.
- У **каждой папки** дерева (в т.ч. вложенной, любого уровня) в режиме
  выбора появился свой чекбокс — отмечает или снимает разом все файлы
  внутри неё, включая файлы во вложенных подпапках. Если внутри отмечена
  только часть файлов — чекбокс папки показывает промежуточное состояние
  (частично заполненный).

### Файлы для переноса
```
backend/patches/index.py       (уже включён в разделы 2/3 выше — переносить один раз)
backend/patches/tests.json     (уже включён в раздел 2 выше — переносить один раз)
src/pages/index/Patches.tsx           (уже включён в раздел 2 выше — переносить один раз)
src/pages/index/PatchesTree.tsx       (уже включён в раздел 2 выше — переносить один раз)
src/pages/index/PatchesTreeFolder.tsx (уже включён в раздел 2 выше — переносить один раз)
src/pages/index/usePatches.ts         (уже включён в раздел 2 выше — переносить один раз)
src/pages/index/patchesUtils.ts       (НОВЫЙ файл в списке переноса — добавлена функция collectFilePaths)
```
Если вы уже перенесли раздел 2 целиком, донести нужно только
`src/pages/index/patchesUtils.ts` — все остальные файлы этой темы уже
содержат нужные правки (backend и фронт обновлялись одним и тем же набором
файлов на протяжении дня).

### Как перенести
```bash

cp update/2026-08-06/backend/patches/tests.json backend/patches/tests.json
cp update/2026-08-06/src/pages/index/Patches.tsx src/pages/index/Patches.tsx
cp update/2026-08-06/src/pages/index/PatchesTree.tsx src/pages/index/PatchesTree.tsx

cp update/2026-08-06/src/pages/index/usePatches.ts src/pages/index/usePatches.ts
```

Backend содержит только новое действие (`zip_bulk`), миграций БД для этой

### Проверка
- В «Патчах» включите «Выбрать файлы», отметьте несколько файлов — кнопка
  «Скачать архивом» должна стать активной и собрать `.zip` со всеми
  отмеченными файлами.
- Отметьте чекбокс у папки — должны отметиться все файлы внутри неё, в т.ч.
  во вложенных подпапках. Снимите чекбокс — все файлы внутри должны
  сброситься.
- Отметьте вручную только часть файлов внутри папки — чекбокс самой папки
  должен показать промежуточное (частично закрашенное) состояние.

## 5. Код ошибки в сообщении о сбое заливки/сверки с лаунчером

Это изменение уже было выпущено ранее и **входит в файл
`src/pages/index/usePatches.ts` выше** — отдельно переносить не нужно, если
вы уже перенесли раздел 2. Напоминание сути: при сбое заливки файла на VPS
лаунчера или сверки с лаунчером сообщение об ошибке теперь содержит
технический код в скобках, например `(код: ssh_error_AuthenticationException)`,
чтобы можно было понять причину без доступа к серверным логам backend.

## 0. Порядок действий (коротко)

1. Сделайте бэкап сервера (файлы + БД).
2. Примените 7 новых миграций (раздел «Миграции» ниже) — по порядку.
3. Скопируйте файлы из папок `backend/`, `src/`, `deploy/` поверх своих.
4. Доустановите Python-зависимость: `pip install pypdf` (или скопируйте
   `deploy/requirements.txt` целиком и выполните `pip install -r deploy/requirements.txt`).
5. Пересоберите фронтенд (`npm run build`) и перезапустите backend-сервис.
6. Новых npm-зависимостей нет — `package.json` не менялся, `npm install` не требуется.

## 1. Раздел «AI»: личные файлы и лимит объёма

**Что нового для сотрудника.** Появился раздел «Мои файлы» — всё, что сотрудник загрузил
в чат или что сгенерировала модель, собрано в один список с деревом папок. Можно удалить
отдельный файл или очистить всё разом, не трогая переписку. Раньше файлы жили только
внутри сообщений и в хранилище: посчитать или убрать их было невозможно.

**Лимит.** У каждого сотрудника есть личный лимит на **суммарный объём** файлов в МБ
(по умолчанию 1024 МБ). Настраивается администратором в Кабинет → Команда, в карточке
сотрудника. В лимит входят **все** файлы — и загруженные вручную, и сгенерированные
моделью (картинки, видео, собранные Excel/Word). Значение 0 полностью запрещает
сотруднику загрузку и генерацию.

Место проверяется **до** обращения к модели: сотрудник не заплатит за видео, которое
некуда сохранить (деньги за генерацию списываются в момент запуска и не возвращаются).

**Сводка по команде.** Кабинет → Управление проектом → Хранилище: кто сколько занимает
места, сколько из этого приходится на сгенерированное, и сумма личных лимитов.

Файлы: `backend/ai/*` (включая новый `userfiles.py`), `backend/admin/index.py`,
`src/pages/index/AiFilesPanel.tsx`, `src/pages/index/useAiFiles.ts`,
`src/pages/cabinet/AiStorageSummary.tsx`, `src/pages/cabinet/CabinetStorage.tsx`,
карточка сотрудника в `src/pages/admin/*`.

## 2. Раздел «AI»: журнал ошибок

Кабинет → «Ошибки AI»: каждая неудача записывается в базу с моделью, действием,

запрос» причину на боевом сервере было не выяснить — логи облачной функции доступны

## 3. Таск-менеджер: крупный блок доработок

**Несколько серверов у задачи и спринта.** Одна правка часто выкатывается сразу на
несколько серверов — раньше приходилось заводить копии задачи. Теперь в форме выбор
галочками. Задача попадает в список каждого своего сервера в разделе «К рестарту», а при
закрытии запись в патчноуты создаётся **для каждого** выбранного сервера. Поле `server`
сохранено для совместимости и хранит первый сервер списка.

**Право «Закрывать задачи».** Раньше закрывать задачи мог только администратор, и отдельного
права не существовало. Теперь в Кабинет → Команда → группа «Задачи» есть флажок
«Закрывать задачи» — его можно выдать сотруднику, не давая полных админских прав. Возврат
из архива и удаление задачи остались только у администратора. У администраторов право
включено по умолчанию, ничего донастраивать не нужно.

**Автор закрытия.** В карточке закрытой задачи и в списке архива видно, кто и когда её
закрыл. Данные записывались и раньше, но наружу не отдавались.

**Архив: сортировка и фильтр.** Сортировка по дате закрытия (новые/старые) и ряд фильтров
по серверам с количеством задач по каждому. Показываются только серверы, по которым в
архиве реально есть задачи.

**Обязательная категория.** При создании задачи категорию теперь нужно выбрать явно —
раньше молча подставлялось «Прочее», и большинство задач оставались непомеченными.
Проверка стоит и на сервере. На редактирование уже существующих задач не влияет.

**Исправлена ошибка счётчика комментариев** на карточках: он читался по жёстко заданному
номеру колонки и сбивался при добавлении любого нового поля в задачу.

Файлы: `backend/tasks/index.py`, `backend/sprints/index.py`, `backend/{admin,auth}/index.py`
(новое право), миграции V0093/V0094, большинство файлов `src/pages/index/`.

## 4. Редактируемые статусы деплоя

Статусы деплоя были жёстко зашиты в коде — добавить свой можно было только правкой кода.
Теперь это справочник: Кабинет → Управление проектом → **«Статусы деплоя»**. Можно
добавлять, переименовывать, менять цвет и иконку, удалять.

Ограничения сделаны намеренно:

- свой статус привязывается к колонке **«К выполнению»** или **«В работе»**;
- колонки «Готово» в выборе нет: единственный статус в ней — системный
  «Можно заливать на лайв», на нём держатся бейдж «Требуется залить в лаунчер»
  и уведомления;
- колонки «На удержании» в выборе нет: она не привязана к статусам — отложить можно
  задачу в любом статусе, и при переносе туда статус сохраняется;
- статусы «Без статуса» и «Можно заливать на лайв» помечены системными: у них можно
  изменить оформление, но нельзя удалить или перенести в другую колонку;
- при удалении статуса задачи с ним переходят в «Без статуса», а не зависают со ссылкой
  на несуществующую стадию.

Названия статусов в уведомлениях и журнале активности теперь тоже берутся из справочника —
раньше был отдельный список в коде, и новый статус попал бы в Telegram голым
идентификатором.

Файлы: `db_migrations/V0095`, `backend/catalog/index.py`, `backend/tasks/index.py`,
`src/lib/catalog.tsx`, `src/pages/cabinet/CabinetDeployStatuses.tsx`,
`src/pages/cabinet/CabinetProject.tsx`, `src/pages/index/sharedConstants.ts`.

## 5. Оформление интерфейса

**Скругления.** Все радиусы теперь считаются от одной переменной `--radius` в
`src/index.css` (раньше ей подчинялись лишь три класса, остальное брало значения по
умолчанию). Значение уменьшено с 12 до 6 пикселей — углы читаются как аккуратная фаска.
Чтобы сделать интерфейс строже или мягче, достаточно поменять это одно число.

**Премиальная тёмная тема.** Фон, карточки и всплывающие окна разведены по плотности —
появилась честная глубина вместо плоскости. Тени пересобраны под тёмный фон (стандартные
рассчитаны на светлый и дают резкий чёрный ореол). Сетка из точек на фоне убрана, вместо
неё две мягкие засветки. Плашки приоритета и сервера стали сдержаннее: цвет держат точка
и тонкая рамка, а не заливка; категория — тихая подпись. Включено сглаживание шрифта,
уточнены трекинг заголовков и моноширинные цифры в счётчиках.

**Прочее.** Подпись под логотипом — «Рабочее пространство». Шапка и боковое меню —
матовое стекло с размытием.

Файлы: `src/index.css`, `tailwind.config.ts`, `src/pages/index/sharedComponents.tsx`,
`src/pages/index/{IndexTopbar,IndexSidebar,BoardTaskCard}.tsx`.

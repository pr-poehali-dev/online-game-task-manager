## Как это работает

### Превью в мессенджерах

Боты мессенджеров, которые строят превью ссылки, не заходят в аккаунт и не выполняют
JS — раньше они всегда получали статичный `index.html` с одним и тем же
`og:title="ЭРА"`. Теперь Nginx по `User-Agent` отличает такого бота от обычного
браузера сотрудника:

- **обычный браузер** — всё как раньше, открывается приложение (SPA);
- **бот-краулер** (Telegram, WhatsApp, Facebook, VK, Discord, Slack, Twitter/X,
  LinkedIn, Skype, Viber) — Nginx отправляет его на новый служебный маршрут в
  backend (`/api/_og/task/{id}`), который отдаёт готовую HTML-страницу с заголовком
  вида **«#141 · Название задачи»**.

Backend узнаёт название задачи через новое публичное действие `action=og_meta` в
`backend/tasks/index.py` — оно **намеренно не требует входа в аккаунт** (как и
положено превью ссылки — иначе бот ничего не увидит), но отдаёт **только номер и
название**, никакого текста описания и никаких других данных задачи наружу не уходит.
Название задачи экранируется от спецсимволов, так что оно не может сломать разметку
страницы, даже если в названии есть `<`, `>` или кавычки.

Если задача была удалена или ссылка битая — превью показывает общий заголовок «ЭРА»
вместо ошибки, ссылка всё равно открывает приложение по клику.

### Номер на карточке, поиск, копирование ссылки

Номер задачи на карточке — это её `id`, тот же, что в адресе `/task/{id}`. Поиск
(`taskMatchesSearch` в `sharedHelpers.ts`) сначала проверяет точное совпадение с
номером (с решёткой или без), и только если не найдено — ищет вхождение в название.

Клик по номеру на карточке сначала пробует скопировать ссылку современным
`navigator.clipboard`, а при отказе браузера (нужен HTTPS и явное разрешение —
без запасного варианта была ошибка «Не удалось скопировать ссылку») подстраховывается
более старым `document.execCommand('copy')` — так ссылка копируется даже там, где новый
Clipboard API недоступен (например внутри iframe).

### Редактирование, реакции и закрепление комментариев

Все три фичи живут в `task_comments` и одном новом связанном справочнике:

- **Редактирование** (`action=comment_edit`) — колонка `task_comments.edited_at`
  (миграция `V0098`). Править может только автор комментария (проверка `user_id`),
  текст и упоминания (`mentions`) перезаписываются, время правки сохраняется и
  показывается в интерфейсе как «(изменено)».
- **Реакции** (`action=comment_reaction_toggle`) — новая таблица
  `task_comment_reactions` (миграция `V0099`, внешние ключи на `task_comments` и
  `users`, уникальный индекс `(comment_id, user_id, emoji)`). Повторный клик по уже
  поставленной реакции убирает её (toggle), а не плодит дубликаты. Набор эмодзи
  ограничен фиксированным списком (`ALLOWED_REACTION_EMOJI` в `backend/tasks/index.py`)
  — так реакции остаются единообразными. При загрузке списка комментариев
  (`action=comments`) реакции всех комментариев задачи подтягиваются ОДНИМ запросом
  (`WHERE comment_id = ANY(...)`), а не по одному на комментарий, чтобы не создавать
  N+1 в длинных обсуждениях.
- **Закрепление** (`action=comment_pin_toggle`) — колонка `task_comments.pinned_at`
  (миграция `V0100`). Закреплять может тот, кто и так управляет ходом задачи: её автор,
  назначенный исполнитель или админ — то же правило прав, что уже используется для
  смены статуса деплоя. Закреплён единовременно только один комментарий на задачу:
  backend сначала снимает `pinned_at` со всех комментариев задачи, затем при
  необходимости ставит его на выбранный. На фронтенде закреплённый комментарий
  сортируется в начало списка (`sortedTopLevel` в `TaskComments.tsx`) независимо от
  времени создания.

Все три действия используют одну и ту же проверку доступа к задаче, что и остальные
операции с комментариями («видеть чужие задачи» либо быть автором/исполнителем/админом),
никаких новых прав в `PermissionKey` не добавлено.

### Починка двойной рамки фокуса

В поле ввода нового комментария и в поле редактирования обёртка подсвечивалась своим
кольцом фокуса (`focus-within:ring`), а само текстовое поле ДОПОЛНИТЕЛЬНО получало ещё
одну глобальную рамку фокуса (общий стиль `:focus-visible` для всех полей на сайте) —
эти два кольца не совпадали по размеру, из-за чего внутри рамки была видна лишняя
горизонтальная полоса. Убран дублирующий эффект у самого текстового поля
(`focus-visible:shadow-none`), осталось одно кольцо на обёртке.

   новый `location` и `map` в начале файла — если вы редактировали свой конфиг вручную,

   - `backend/tasks/index.py`
   - `deploy/server.py`
   - `deploy/nginx.conf`
   - `src/pages/Index.tsx`
   - `src/pages/index/IndexTopbar.tsx`

   - `src/pages/index/TaskModal.tsx`
   - `src/pages/index/TaskModalShared.tsx`
3. Перезапустите backend:
   ```bash
   sudo systemctl restart era-backend
   ```
4. Проверьте и перезагрузите Nginx:
   ```bash
   sudo nginx -t && sudo systemctl reload nginx
   ```
5. Пересоберите фронтенд:
   ```bash
   npm run build
   ```
6. `npm install` и `pip install` не требуются — список зависимостей не менялся.

## Проверка после установки

Поставьте ссылку на реальную задачу (например `https://ВАШ-ДОМЕН/task/1`) в чат
Telegram — превью должно показать «#1 · Название задачи». Если превью не обновилось —
Telegram какое-то время кэширует уже показанную карточку для конкретной ссылки; можно
проверить свежим curl с поддельным User-Agent бота:

```bash
curl -A "TelegramBot (like TwitterBot)" https://ВАШ-ДОМЕН/task/1
```

В ответе должен быть `<title>#1 · ...</title>` — если вместо этого вернулась обычная
HTML-страница приложения (со ссылками на `/assets/index-*.js`), проверьте, что Nginx
конфиг перезагружен (`nginx -t` без ошибок) и backend перезапущен.

На доске: карточка задачи должна показывать номер перед названием, поле поиска рядом
с фильтром серверов должно находить задачу по номеру, а клик по номеру на карточке —
копировать ссылку и показывать уведомление.

В обсуждении задачи: у своего комментария должна появиться кнопка «Изменить», под
комментарием — кнопка со смайликом для реакций (клик по эмодзи ставит реакцию, повторный
клик снимает), а у автора/исполнителя/админа — кнопка «Закрепить», после которой
комментарий переезжает наверх списка с пометкой «📌 Закреплено». В поле ввода
комментария при клике внутрь должна быть только одна ровная рамка без лишней полосы
посередине.

## Проверки, выполненные при сборке

- **Хардкоды платформы.** `backend/tasks/index.py` уже содержал (до этого апдейта)
  облачные значения по умолчанию `S3_ENDPOINT`/`_public_url` — они не относятся к
  правкам этого патча, но раз файл копируется целиком, заодно приведён к тому же
  self-hosted паттерну, что и остальные backend-файлы проекта (`S3_ENDPOINT` теперь
  `http://127.0.0.1:9000`, публичная ссылка собирается из `S3_PUBLIC_URL` /
  `CDN_BASE_URL`, иначе из `S3_ENDPOINT` + `S3_BUCKET`). `deploy/server.py` и
  `deploy/nginx.conf` хардкодов платформы не содержат — новый код использует только
  `APP_URL` (уже настроен в вашем `.env`, см. `era-backend-env.path`/`.service`).
  Файлы интерфейса (`src/pages/...`) не работают с S3/CDN — ссылка на задачу для
  копирования собирается из `window.location.origin` (домен, на котором открыт сайт),
  никаких хардкодов.
- **Dev-only компоненты.** Ни один из изменённых файлов не импортирует
  `DevOnlyLoginButton`.
- **Миграции.** Три новых (`V0098`, `V0099`, `V0100`) — все через `ADD COLUMN IF NOT
  EXISTS` / `CREATE TABLE IF NOT EXISTS`, повторный запуск безопасен, старые данные не
  трогают. Внешние ключи новой таблицы `task_comment_reactions` ссылаются на уже
  существующие `task_comments` и `users`.
- **Зависимости.** `deploy/requirements.txt`, `backend/tasks/requirements.txt` и
  `package.json` не менялись — новый backend-код использует только стандартную
  библиотеку Python (`html`, `json`) и уже установленный `fastapi`, новый
  фронтенд-код — уже подключённый `sonner` и `lucide-react` (иконки `Pencil`, `Pin`,
  `SmilePlus` уже входят в пакет).
- **Права доступа.** Редактирование ограничено автором комментария, закрепление —
  автором/исполнителем задачи или админом (та же проверка, что уже используется для
  смены статуса деплоя), реакции доступны всем, кто видит комментарии задачи. Новых
  ключей в `PermissionKey` не добавлено.
- **Проверено end-to-end** локальным тестовым запуском FastAPI-обёртки: маршрут
  `/api/_og/task/{id}` отдаёт корректный HTML с заголовком `#id · Название` для
  существующей задачи, фолбэк на общий заголовок «ЭРА» — для несуществующей; обычные
  маршруты `/api/tasks` (требует токен) и `/api/health` продолжают работать без
  изменений. Новые действия `comment_edit`, `comment_reaction_toggle`,
  `comment_pin_toggle` без токена корректно отвечают 401 (см. `backend/tasks/tests.json`).
- **Сборка.** `npm run build` и `tsc --noEmit` проходят без ошибок по изменённым
  файлам интерфейса.

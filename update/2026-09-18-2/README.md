# Обновления от 18 сентября (2): увеличен таймаут ожидания ответа ИИ в чате

Точечный фикс поверх всех уже установленных `update/2026-09-18/` и более ранних. Одна тема.

1. **Таймаут ожидания ответа модели в обычном чате поднят до 150 секунд.** Раньше отправка
   сообщения (`action=send_message`) и перегенерация ответа (`action=regenerate`) в разделе «AI»
   не передавали свой таймаут явно — использовалось значение по умолчанию из
   `_aitunnel_request` (45 секунд). Для более медленных reasoning-моделей этого не хватало, и
   запрос обрывался с ошибкой `TimeoutError: The read operation timed out` в логах backend, а
   сотрудник видел ошибку вместо ответа. Заполнение документов по шаблону (`backend/ai/documents.py`)
   этой проблемы не имело — там таймаут уже был явно указан как 90 секунд.

## Как это работает

`backend/ai/generate.py`:
- `handle_send_message` — вызов `_aitunnel_request('/chat/completions', ...)` теперь передаёт
  `timeout=150` (было — не передавался, действовал дефолт 45 сек).
- `handle_regenerate` — тот же вызов для перегенерации последнего ответа, тоже `timeout=150`.

Прочие обращения к AI Tunnel (каталог моделей, баланс, генерация изображений/видео, автоназвание
диалога, заполнение документов) не менялись — у них уже были свои таймауты, подобранные под
конкретную задачу.

⚠️ Если у вас в nginx настроен `proxy_read_timeout`/`proxy_send_timeout` меньше 150 секунд для
вашего домена — nginx оборвёт соединение раньше, чем сработает этот таймаут в коде, и ошибка
останется. Проверить: `grep -rn "proxy_read_timeout\|proxy_send_timeout" /etc/nginx/`. На боевом
сервере forge.la2era.com уже стоит 180 секунд — запаса достаточно, донастройка не требуется.

## 0. Порядок действий

1. Скопируйте файл поверх своего:
   - `backend/ai/generate.py`
2. Миграции БД — **не требуются**, схема не менялась.
3. npm/pip-зависимости — **не требуются**, список не менялся.
4. Пересобирать фронтенд — **не требуется**, это чисто backend-правка.
5. Перезапустите backend (self-hosted `deploy/server.py` грузит все функции при старте процесса):
   ```bash
   sudo systemctl restart era-backend.service
   ```
6. Nginx этот апдейт не затрагивает (см. предупреждение выше — донастройка нужна, только если у
   вас таймаут прокси меньше 150 секунд).

## Проверка после установки

- Откройте раздел «AI» → обычный чат, отправьте сообщение медленной/«думающей» модели, которая
  раньше падала с ошибкой таймаута. Ответ должен дождаться завершения (до 150 секунд) вместо
  обрыва соединения.
- В логах backend не должно быть новых записей `TimeoutError: The read operation timed out` для
  запросов `/chat/completions` из обычного чата.

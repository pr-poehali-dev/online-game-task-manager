# Обновления от 18 сентября (4): честный стриминг ответа ИИ в чате (только self-hosted)

Точечный апдейт поверх всех уже установленных `update/2026-09-18-3/` и более ранних. Одна тема,
но с важной оговоркой ниже.

1. **Ответ модели в обычном чате теперь появляется на экране постепенно, по мере генерации** —
   как в большинстве современных чат-интерфейсов, а не одним куском после долгого ожидания.
   Раньше сотрудник видел индикатор «печатает» и получал весь ответ разом, только когда модель
   полностью закончила генерацию (это могло занимать десятки секунд для длинных ответов).

⚠️ **Важная техническая оговорка.** Эта возможность работает **только на вашем self-hosted
сервере** (там backend — обычный процесс FastAPI, который умеет держать соединение открытым и
отдавать данные по частям). На облачной версии poehali.dev, где ведётся разработка, у облачных
функций жёсткий контракт «запрос → готовый ответ одним куском» — там стриминг физически
невозможен, и на превью-окружении вы увидите прежнее поведение (ответ целиком после ожидания).
После установки этого апдейта именно на вашем сервере (`forge.la2era.com`) стриминг заработает
в полную силу.

## Как это работает

### Новый эндпоинт только для self-hosted

- `backend/ai/stream.py` — новый модуль. Он **не входит** в общую карту действий раздела «AI»
  (`backend/ai/index.py` его не знает) — вместо этого `deploy/server.py` подключает его напрямую
  и регистрирует отдельный маршрут `POST /api/ai/stream`, если файл `stream.py` присутствует.
  Если бы вы забыли скопировать этот файл — сервер просто не завёл бы маршрут, ошибки не будет.
- Формат ответа — Server-Sent Events (SSE), тот же, что использует сам AI Tunnel: событие
  `delta` на каждый кусочек текста, событие `done` в конце с итоговой стоимостью, событие `error`
  при сбое.
- `deploy/server.py` — добавлен маршрут `/api/ai/stream` через `StreamingResponse` (FastAPI),
  плюс обработка `OPTIONS` для CORS.
- `deploy/nginx.conf` — для нового пути добавлен отдельный `location /api/ai/stream` с
  `proxy_buffering off`. Это критично: без отключения буферизации Nginx копил бы весь ответ
  и отдавал его браузеру одним куском, сводя на нет весь смысл стриминга.

### Фронтенд

- `src/pages/index/sharedHelpers.ts` — добавлена константа `AI_STREAM_URL` (адрес нового
  эндпоинта, строится из уже существующего `AI_URL`).
- `src/pages/index/useAiSection.ts` — при отправке сообщения в обычном чате (режимы chat/code,
  без вложений) фронт сначала пробует потоковый запрос. Если эндpoint недоступен (например, вы
  ещё не установили этот апдейт, либо открыт облачный preview) — получает 404 и **автоматически,
  незаметно для сотрудника**, откатывается на прежний обычный запрос. Это происходит один раз за
  сессию вкладки браузера — дальше фронт запоминает, что стрим недоступен, и больше не пробует
  его при каждой отправке (чтобы не делать лишний сетевой запрос на каждое сообщение).
- Режим «Документы» и сообщения с вложениями по-прежнему идут только обычным запросом — стрим
  поддерживает только простой текстовый чат.

## 0. Порядок действий

1. Скопируйте файлы поверх своих:
   - `backend/ai/stream.py` — **новый файл**, создайте папку/файл, если их ещё нет
   - `deploy/server.py`
   - `deploy/nginx.conf`
   - `src/pages/index/sharedHelpers.ts`
   - `src/pages/index/useAiSection.ts`
2. Миграции БД — **не требуются**, схема не менялась.
3. npm/pip-зависимости — **не требуются**, список не менялся (FastAPI `StreamingResponse` уже
   доступен в составе `fastapi`, отдельный пакет ставить не нужно).
4. Пересоберите фронтенд:
   ```bash
   npm run build
   ```
5. Обновите конфигурацию Nginx и перезапустите его:
   ```bash
   sudo nginx -t && sudo systemctl reload nginx
   ```
6. Перезапустите backend:
   ```bash
   sudo systemctl restart era-backend.service
   ```

## Проверка после установки

- Откройте раздел «AI» → обычный чат, отправьте сообщение — текст ответа должен появляться на
  экране постепенно, по мере генерации, а не одним куском после ожидания.
- Откройте вкладку «Сеть» в инструментах разработчика браузера (F12) — запрос должен идти на
  `/api/ai/stream` со статусом 200 и типом ответа `text/event-stream`.
- Отправьте сообщение с прикреплённым файлом или переключитесь в режим «Документы» — эти сценарии
  должны по-прежнему работать как раньше (обычным запросом, без стриминга).
- Если что-то пошло не так со стримингом — сотрудник всё равно должен получить ответ (просто без
  постепенного появления текста): фронт молча откатывается на старый способ при любой ошибке
  нового эндпоинта.

## Проверки, выполненные при сборке

- **Хардкоды платформы.** Во всех новых/изменённых файлах команда
  `grep -rn "poehali.dev" update/2026-09-18-4/` находит только текстовые пояснения в комментариях
  (о том, что стриминг не работает в облаке) — не адреса запросов в коде. Это допустимое
  исключение по правилу проверки.
- **Новые pip-зависимости.** Не добавлялись — `StreamingResponse` уже часть пакета `fastapi`,
  который и так есть в `deploy/requirements.txt`.
- **Dev-only компоненты.** Не затронуты.
- **Совместимость со старым поведением.** Новый маршрут `/api/ai/stream` — строго дополнительный,
  существующий `/api/ai` (action=send_message и все остальные действия) не менялся ни в одной
  строке. Если апдейт не устанавливать вовсе — ничего не сломается, просто не будет стриминга.

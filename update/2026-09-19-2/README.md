# Обновления от 19 сентября (2): фикс синхронизации прав «AI»/«Логи» + метки веб-поиска в списке моделей

Апдейт поверх всех уже установленных `update/2026-09-19/` и более ранних. Две несвязанные темы,
собранные в один патч по дате: (1) критичный фикс backend, (2) визуальные доработки списка моделей.

## 1. Исправлен баг — выданные права «AI»/«Логи» не доходили до сотрудника

Администратор выдаёт сотруднику право доступа к разделу «AI» (или «Логи») через панель
управления командой — право сохраняется в базе данных корректно. Но у сотрудника пункт «AI» в
шапке сайта не появляется **никогда** — ни после обновления страницы, ни после повторного входа
в систему. При этом открыть раздел по прямой ссылке сотрудник МОЖЕТ — сама проверка доступа на
сервере работает верно, при генерации контента ошибок нет.

**Причина:** функция, которая формирует список прав пользователя для ответа на запрос «кто я»
(вызывается при каждом входе и каждом обновлении страницы), была продублирована в нескольких
backend-файлах и рассинхронизировалась. В файле, который отвечает на панели администратора
(`backend/admin/index.py`), список прав обновлялся и знает про `logs_view`/`ai_access`. А в
файлах, которые отвечают сотруднику при входе/обновлении страницы
(`backend/auth/index.py`, `backend/login-code/index.py`) — список остался старым, без этих двух
прав. Из-за этого сервер каждый раз честно забывал сообщить сотруднику, что у него есть новое
право — не проблема кэша браузера, а сервер отдавал неполные данные.

### Как это работает

`backend/auth/index.py` и `backend/login-code/index.py` (это два независимых способа входа в
систему — обычный вход и вход по коду через Telegram-бота, у каждого была своя копия одной и той
же функции):
- В список `ALL_PERMISSIONS` добавлены `logs_view` и `ai_access` (были в
  `backend/admin/index.py`, отсутствовали здесь).
- В `_effective_perms()` эти два права добавлены в исключение «по умолчанию False, даже если
  роль admin» — той же логике, что уже была для `patch_edit`/`team_manage`, и как это уже
  корректно устроено в `backend/admin/index.py`.

Другие backend-файлы с похожей (но своей, более узкой) копией той же функции —
`backend/ideas`, `backend/knowledge`, `backend/patches`, `backend/sprints`, `backend/tasks` —
**не затронуты и трогать не нужно**: они используют список прав только для ВНУТРЕННИХ проверок
своих собственных действий (создание задачи, идеи, статьи и т.п.) и никогда не проверяют
`ai_access`/`logs_view` — отсутствие этих ключей там ни на что не влияет.

## 2. Метки веб-поиска в списке моделей раздела «AI»

Раньше в списке выбора модели не было видно, какие модели умеют искать в интернете (эта
возможность подключена автоматически ко всем сообщениям обычного чата, см. `update/2026-09-19/`,
но не все модели ей пользуются). Теперь:

1. **Синяя плашка «🌐 Веб-поиск»** — появляется прямо в списке рядом с именем модели, у каждой
   модели, которая реально умеет пользоваться этим инструментом (определяется по полю
   `web_search_cost` в каталоге AI Tunnel — оно присутствует ТОЛЬКО у поддерживающих моделей).
2. **Переключатель «Только с веб-поиском»** — под вкладками Рекомендуемые/Продвинутые/Дешёвые.
   Это НЕ отдельная четвёртая вкладка, а фильтр, который накладывается ПОВЕРХ любой из трёх —
   можно, например, включить одновременно «Дешёвые» и «Только с веб-поиском», чтобы увидеть
   именно дешёвые модели с доступом в интернет, а не выбирать между категориями по цене и по
   умению искать.

### Как это работает

- `src/pages/index/AiTypes.ts` — у `AiModelInfo` новое опциональное поле `web_search_cost` (цена
  инструмента из каталога, наличие поля = модель умеет искать).
- `src/pages/index/AiModelPicker.tsx` — плашка в строке модели (стиль как у существующей плашки
  «Устарела», но синим цветом, с иконкой `Globe`) и переключатель `webSearchOnly`, который
  участвует в фильтрации списка вместе с текущей вкладкой.

## 0. Порядок действий

1. Скопируйте файлы поверх своих:
   - `backend/auth/index.py`
   - `backend/login-code/index.py`
   - `src/pages/index/AiModelPicker.tsx`
   - `src/pages/index/AiTypes.ts`
2. Миграции БД — **не требуются**, схема не менялась.
3. npm/pip-зависимости — **не требуются**, список не менялся.
4. Пересоберите фронтенд (нужно из-за пункта 2 — правки в `.tsx`/`.ts`):
   ```bash
   npm run build
   ```
5. Перезапустите backend (self-hosted `deploy/server.py` грузит все функции при старте процесса):
   ```bash
   sudo systemctl restart era-backend.service
   ```

## Проверка после установки

- Выдайте сотруднику право «AI» (или «Логи») через панель управления командой.
- Попросите сотрудника обновить страницу (F5) — пункт «AI» (или «Логи») должен сразу появиться
  в шапке, без повторного входа в систему.
- Если сотрудник заходит через код в Telegram-боте (не через обычную кнопку входа) — право тоже
  должно появиться сразу после подтверждения кода.
- Откройте раздел «AI» → выбор модели — у части моделей (в основном флагманы GPT-5.x/6, Gemini)
  должна быть видна синяя плашка «Веб-поиск». Включите переключатель «Только с веб-поиском» —
  список должен сузиться, оставив только такие модели, независимо от выбранной вкладки.

## Проверки, выполненные при сборке

- **Хардкоды платформы.** `backend/login-code/index.py` S3 не использует, хардкодов нет.
  `backend/auth/index.py` использует S3 (аватарки) — исправлен на self-hosted паттерн
  (`endpoint_url` → `http://127.0.0.1:9000`, `_public_url` fallback → сборка адреса из
  `S3_ENDPOINT`+`S3_BUCKET` вместо `cdn.poehali.dev/projects/...`), тот же регресс, что регулярно
  возвращается в файлах с S3 при копировании из общего репозитория. Фронтенд-файлы
  (`AiModelPicker.tsx`, `AiTypes.ts`) обращений к `poehali.dev` не содержат вовсе.
- **Новые pip/npm-зависимости.** Не добавлялись — backend-правка только в существующей функции
  проверки прав, фронтенд-правка использует уже подключённую иконку `Globe` (lucide-react) и
  существующий паттерн бейджа/вкладок, `package.json` в диапазоне этих правок не менялся.
- **Dev-only компоненты.** Не затронуты.
- **Совместимость со старым поведением.** Backend-правка только ДОБАВЛЯЕТ два поля в список прав,
  отдаваемых пользователю — ничего не убирает и не меняет для остальных прав. Фронтенд-правка
  добавляет визуальный индикатор и необязательный фильтр — поведение выбора модели без плашки
  не меняется.

# Обновления от 20 сентября: модель не "слетает" в диалоге + чекбокс "Веб-поиск" над полем ввода

Апдейт поверх `update/2026-09-19-2/` и более ранних. Две связанные доработки раздела «AI».

## 1. Выбранная модель больше не сбрасывается в существующем диалоге

**Было:** при первом сообщении в новом диалоге модель сохранялась правильно, но если сотрудник
ПОЗЖЕ, в середине переписки, переключал модель на другую (например с дешёвой на более мощную для
сложного вопроса) — при следующем открытии этого же диалога модель "откатывалась" обратно на ту,
что была выбрана при СОЗДАНИИ диалога, а не на последнюю, которой реально пользовались.

**Причина:** модель записывалась в базу данных (`ai_chats.model`) только один раз — при создании
диалога первым сообщением. При каждом следующем сообщении в базе обновлялось только время
последней активности (`updated_at`), а сама модель — нет. Открывая диалог заново, интерфейс
подставляет в шапку именно сохранённое в базе значение (см. `useAiSection.ts`, `loadChat`) — и
получал устаревшее.

**Исправление:** `backend/ai/generate.py`, `backend/ai/stream.py`, `backend/ai/documents.py` —
модель теперь сохраняется в `ai_chats.model` при КАЖДОЙ отправке сообщения (обычной, потоковой,
перегенерации ответа, сборке документа), а не только при создании диалога. Работает отдельно для
каждого диалога — в разных чатах можно держать разные модели одновременно, как и раньше.

## 2. Чекбокс "Веб-поиск" над полем ввода

**Было:** инструмент поиска в интернете (`aitunnel:web_search`) подключался автоматически КО ВСЕМ
сообщениям обычного чата всегда, без возможности увидеть или отключить это — сотрудник не мог ни
проверить, будет ли модель искать в сети, ни отказаться от этого (например если явно нужен ответ
только по знаниям самой модели, без обращения к интернету — поиск может немного увеличивать время
ответа и стоимость запроса у моделей, которые ценообразуют инструмент отдельно).

**Стало:** над полем ввода в режимах «Чат» и «Код» появился явный переключатель «Веб-поиск»
(с иконкой глобуса). Работает по тому же принципу, что и выбор модели:

- **Включён по умолчанию** — поведение "из коробки" не поменялось для тех, кто ничего не трогает.
- **Сохраняется ОТДЕЛЬНО для каждого диалога** (`ai_chats.web_search_enabled`) — как и модель, не
  сбрасывается при переключении между чатами или обновлении страницы.
- **Дизаблится (без возможности включить), если у выбранной модели нет самой способности искать в
  интернете** — определяется по тому же признаку каталога AI Tunnel (`web_search_cost`), что уже
  показывает синюю плашку «Веб-поиск» в списке моделей (см. `update/2026-09-19/`). Наведение
  курсора поясняет, почему переключатель недоступен.
- Не показывается в режимах «Документы»/«Изображения»/«Видео» — там инструмент неприменим (модель
  для документов отдаёт структуру файла, изображения/видео — отдельные API без этого инструмента).

### Как это работает

- `db_migrations/V0104__ai_chats_web_search_enabled.sql` — новая колонка
  `ai_chats.web_search_enabled BOOLEAN NOT NULL DEFAULT true`.
- `backend/ai/common.py` — `_chat_to_dict` возвращает новое поле `webSearchEnabled`.
- `backend/ai/chats.py` — `list_chats`/`get_chat` читают новую колонку из БД.
- `backend/ai/generate.py`, `backend/ai/stream.py` — поле `webSearch` в теле запроса
  (`send_message`/поток) управляет тем, добавлять ли `tools: [{"type": "aitunnel:web_search"}]` в
  запрос к AI Tunnel; отсутствие поля (старый закешированный фронт) трактуется как `true` —
  поведение не меняется молча для тех, кто ещё не обновил вкладку в браузере. `regenerate` читает
  сохранённое значение из БД по `chatId` (та же логика, что уже была у модели для перегенерации).
- `src/pages/index/useAiSection.ts` — состояние `webSearch`, восстанавливается из БД при открытии
  существующего диалога (`loadChat`), сбрасывается на `true` при создании нового
  (`handleNewChat`), передаётся в тело каждого запроса отправки сообщения.
- `src/pages/index/AiComposer.tsx` — сам переключатель над полем ввода, только для режимов
  chat/code, дизаблится через новый проп `webSearchSupported`.
- `src/pages/index/AiChatPane.tsx`, `src/pages/index/Ai.tsx` — пробрасывают состояние/колбэк вниз
  по дереву компонентов.
- `src/pages/index/AiTypes.ts` — новое поле `webSearchEnabled` в `AiChatSummary`, уточнён
  комментарий про `web_search_cost` (раньше говорил "подключается автоматически" — теперь
  "по чекбоксу").
- `src/pages/index/AiModelPicker.tsx` — уточнена подсказка у синей плашки «Веб-поиск» в списке
  моделей (теперь ссылается на переключатель, а не на автоматическое подключение).

## Порядок действий

1. Примените миграцию БД (добавляет колонку с безопасным значением по умолчанию — старые диалоги
   автоматически получат `web_search_enabled = true`, то есть прежнее поведение):
   ```bash
   psql "$DATABASE_URL" -f db_migrations/V0104__ai_chats_web_search_enabled.sql
   ```
2. Скопируйте файлы поверх своих:
   - `backend/ai/chats.py`
   - `backend/ai/common.py`
   - `backend/ai/documents.py`
   - `backend/ai/generate.py`
   - `backend/ai/stream.py`
   - `src/pages/index/Ai.tsx`
   - `src/pages/index/AiChatPane.tsx`
   - `src/pages/index/AiComposer.tsx`
   - `src/pages/index/AiModelPicker.tsx`
   - `src/pages/index/AiTypes.ts`
   - `src/pages/index/useAiSection.ts`
3. npm/pip-зависимости — **не требуются**, списки не менялись.
4. Пересоберите фронтенд:
   ```bash
   npm run build
   ```
5. Перезапустите backend:
   ```bash
   sudo systemctl restart era-backend.service
   ```

## Проверка после установки

- Откройте существующий диалог в разделе «AI», переключите модель на другую, отправьте
  сообщение, затем откройте другой диалог и вернитесь обратно — модель должна остаться той,
  что вы выбрали последней, а не откатиться на исходную.
- В режиме «Чат» или «Код» проверьте, что над полем ввода появился переключатель «Веб-поиск» —
  по умолчанию включён (подсвечен синим).
- Выберите модель БЕЗ плашки «Веб-поиск» в списке моделей — переключатель должен стать
  неактивным (серым, курсор показывает подсказку почему).
- Выключите переключатель, отправьте сообщение с вопросом про текущие события — модель НЕ должна
  обращаться к интернету за ответом. Включите обратно — должна снова искать при необходимости.
- Обновите страницу — и выбранная модель, и состояние переключателя «Веб-поиск» должны остаться
  такими, какими вы их оставили в этом диалоге.

## Проверки, выполненные при сборке

- **Хардкоды платформы.** `backend/ai/common.py` использует S3 (вложения/сгенерированные файлы) —
  исправлен на self-hosted паттерн (`endpoint_url` → `http://127.0.0.1:9000`, `_public_url`
  fallback → сборка адреса из `S3_ENDPOINT`+`S3_BUCKET` вместо `cdn.poehali.dev/projects/...`),
  тот же регресс, что регулярно возвращается в файлах с S3 при копировании из общего репозитория.
  Остальные скопированные backend-файлы (`chats.py`, `documents.py`, `generate.py`, `stream.py`)
  своего S3-клиента не создают, хардкодов не содержат. Упоминание `poehali.dev` в комментарии
  `backend/ai/stream.py` и `src/pages/index/useAiSection.ts` — осознанное текстовое пояснение
  разницы между облачными функциями и self-hosted окружением, не адрес запроса, трогать не нужно.
- **Новые pip/npm-зависимости.** Не добавлялись — `backend/ai/requirements.txt` не менялся,
  фронтенд использует уже подключённую иконку `Globe` (lucide-react) и существующий паттерн
  переключателя (тот же, что фильтр «Только с веб-поиском» в `AiModelPicker.tsx` из
  `update/2026-09-19/`).
- **Dev-only компоненты.** Не затронуты.
- **Совместимость со старым поведением.** Миграция даёт всем существующим диалогам
  `web_search_enabled = true` — поведение не меняется для тех, кто не трогает новый переключатель.
  Backend трактует отсутствие поля `webSearch` в запросе (старый закешированный фронт) как `true`
  — тот же принцип обратной совместимости.

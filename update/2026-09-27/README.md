# Обновление от 27 сентября: набор текста в разделе «AI» больше не тормозит в длинных диалогах

Апдейт поверх `update/2026-09-20/` и более ранних. Одна тема — производительность, без изменений
поведения или БД.

## Печать в поле ввода не лагает в длинных диалогах

**Было:** в диалогах с длинной историей (особенно если в ответах моделей есть блоки кода с
подсветкой синтаксиса) набор текста в поле ввода ощутимо подтормаживал — буквы появлялись рывками,
с задержкой около 1-2 секунд на каждое нажатие клавиши.

**Причина:** состояние поля ввода (`input`) и данные ленты сообщений (`messages`) хранятся в одном
общем хуке `useAiSection.ts`. Изменение `input` на каждый символ вызывало ре-рендер всего дерева
компонентов раздела, включая `AiMessageList` — компонент ленты не был обёрнут в `React.memo`, поэтому
React заново перерисовывал ВСЮ историю переписки на каждую напечатанную букву, включая разбор
markdown (`ReactMarkdown`) и подсветку синтаксиса кода в каждом сообщении ассистента — самая тяжёлая
часть рендера, не имеющая никакого отношения к полю ввода.

**Исправление:** `src/pages/index/AiMessageList.tsx` — компонент обёрнут в `React.memo`, чтобы
перерисовываться только когда реально меняются его собственные пропсы (новое сообщение, статус
отправки, режим и т.п.), а не при любом ре-рендере родителя. Одного `memo` недостаточно: колбэки,
передаваемые в этот компонент из `useAiSection.ts` (`handleRegenerate`, `handleTogglePinnedMessage` и
другие функции, объявленные там же), были обычными функциями и пересоздавались заново при КАЖДОМ
рендере хука — новая ссылка на функцию каждый раз ломала бы `memo`, сводя оптимизацию на нет. Поэтому
`src/pages/index/useAiSection.ts` — эти функции завёрнуты в `useCallback` с точными зависимостями,
чтобы сохранять одну и ту же ссылку между рендерами, пока реально нужные им данные не меняются.

### Как это работает

- `src/pages/index/AiMessageList.tsx` — экспорт обёрнут в `memo(...)`, поведение и разметка внутри
  компонента не изменились ни на пиксель.
- `src/pages/index/useAiSection.ts` — `handleRegenerate`, `handleRenameChat`, `handleTogglePinned`,
  `handleDeleteChat`, `handleTogglePinnedMessage` переведены с обычных объявлений функций на
  `useCallback` с явными зависимостями (`activeChatId`, `sending`, `model`, `loadChats` — где нужно).
  Логика внутри каждой функции не менялась.

Чисто фронтенд-оптимизация: нет изменений API, БД, поведения для пользователя (все действия работают
ровно так же, только печать текста стала мгновенной).

## Порядок действий

1. Скопируйте файлы поверх своих:
   - `src/pages/index/AiMessageList.tsx`
   - `src/pages/index/useAiSection.ts`
2. Миграции БД — **не требуются**.
3. npm/pip-зависимости — **не требуются**, списки не менялись.
4. Пересоберите фронтенд:
   ```bash
   npm run build
   ```
5. Backend не затронут — перезапускать `era-backend.service` не нужно.

## Проверка после установки

- Откройте в разделе «AI» диалог с длинной историей (желательно с несколькими ответами, содержащими
  блоки кода).
- Начните быстро печатать в поле ввода — текст должен появляться без рывков и задержек, сразу вслед
  за нажатием клавиш.
- Убедитесь, что остальные действия в диалоге по-прежнему работают: закрепление сообщений (звёздочка),
  перегенерация последнего ответа, переключение между диалогами, переименование и удаление диалога.

## Проверки, выполненные при сборке

- **Хардкоды платформы.** Оба файла не работают с S3/сетевыми адресами напрямую — `grep -n
  "poehali.dev" update/2026-09-27/src/pages/index/*.tsx` находит только одно осознанное текстовое
  упоминание в комментарии `useAiSection.ts` (про облачные функции poehali.dev vs self-hosted), не
  адрес запроса — трогать не нужно.
- **Новые pip/npm-зависимости.** Не добавлялись.
- **Dev-only компоненты.** Не затронуты.
- **Миграции БД.** Не требуются — изменения чисто в рендеринге React, структура данных не менялась.
